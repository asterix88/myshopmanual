Cara kerja robot Apps Script untuk sheet Daily Inspection

Penjelasan untuk siapa pun yang nanti merawat fitur ini, tanpa harus bertanya ke Anas atau ke Claude: apa saja bagiannya, bagaimana data mengalir, isi kodenya, cara memasang, dan apa yang dilakukan kalau ada masalah.

1. Gambaran besar

Google hanya mengizinkan aplikasi menulis ke Google Sheet kalau ada akun Google yang bertanggung jawab, meskipun link sheet terbuka untuk diedit siapa saja. Apps Script adalah program kecil milik Google yang berjalan di server Google atas nama satu akun Gmail. Kita memakai satu Gmail khusus, disebut akun robot, sebagai "tangan" yang membuka sheet.

HP mekanik tidak pernah bicara langsung ke Google. Semua lewat server MyManual, yang memeriksa login NRP dan section, lalu meneruskan permintaan ke robot dengan kode rahasia.

3. Alur membuka daftar temuan

sequenceDiagram
  participant HP as HP mekanik
  participant W as Server MyManual
  participant R as Robot Apps Script
  participant S as Google Sheet
  HP->>W: GET /inspection (token login NRP)
  W->>W: cek token, ambil section NRP (TRACK / WHEEL / SUPPORT)
  W->>R: {key, op: "read", ranges: tab section + T3 + POP UNIT}
  R->>R: KEY cocok?
  R->>S: getDisplayValues() tiap range
  S-->>R: isi sel seperti tampil di sheet
  R-->>W: {values: [...]}
  W->>W: susun temuan, OPEN/CLOSE, daftar GL, POP UNIT
  W-->>HP: JSON (hanya section NRP itu)
  HP->>HP: simpan salinan di HP (inspection.json)

Robot hanya membaca persis range yang diminta. Pilihan tab per section, penyaringan, dan pengurutan dikerjakan server, jadi skrip robot tetap pendek dan jarang perlu diubah.

4. Alur mengisi Action dan menambah temuan

sequenceDiagram
  participant HP as HP mekanik
  participant W as Server MyManual
  participant R as Robot Apps Script
  participant S as Google Sheet
  HP->>HP: masuk antrean (belum terkirim)
  HP->>W: POST /inspection/add {unit, HM, tanggal, leader, problem}
  W->>R: read: isi tab + POP UNIT
  R-->>W: baris-baris sheet
  W->>W: cek unit di POP, cari baris kosong pertama (F dan J kosong)
  W->>R: write: data sel + guard "baris F/J harus masih kosong"
  R->>R: kunci (LockService), cek guard
  alt baris masih kosong
    R->>S: setValues (seperti mengetik)
    R-->>W: {ok: true}
    W-->>HP: berhasil, keluar dari antrean
  else baris keburu diisi HP lain
    R-->>W: {error: "taken"}
    W->>R: baca lagi, pakai baris kosong berikutnya
  end
  • Isi Action: server menulis kolom K pada baris temuan. Rumus STATUS di sheet otomatis berubah menjadi CLOSE. Kalau admin sudah mengurutkan ulang sheet, server mencari baris itu lagi dari kode unit dan problem.
  • Temuan baru: baris di bawah data sudah berisi rumus No, REMARK, STATUS dan SECTION. Server mengisi kolom B sampai J, rumus STATUS di M, dan SECTION di Q: rumus VLOOKUP kalau unit ada di POP UNIT, atau teks section NRP kalau belum ada.
  • LAST UPDATE (sel T3) diisi jam WIB setiap ada perubahan dari app.
  • Kirim dua kali? Setiap tambahan temuan membawa id unik. Kalau HP mengirim ulang karena jawaban sebelumnya hilang, server tahu dan tidak menulis dua kali.

5. Isi kode robot, bagian per bagian

File lengkap: tools/daily-inspection.gs di repo. Seluruhnya sekitar 100 baris.

a. Pengaturan

const KEY = 'GANTI_DENGAN_KODE_RAHASIA';
const SHEET_ID = '1fm-KQv-b1ZKV08oT45LJ-GxEL6meSieANMF-Bf-Tw-E';

KEY adalah kode rahasia, harus sama persis dengan GitHub secret SHEET_SCRIPT_KEY. Selama masih tertulis GANTI_DENGAN_KODE_RAHASIA, robot menolak semua permintaan. SHEET_ID adalah bagian link sheet di antara /d/ dan /edit.

b. Pintu masuk: doPost

Google menjalankan doPost setiap kali server mengirim permintaan ke link Web App. Langkah pertama: baca pesan JSON dan periksa kode rahasia. Tanpa kode yang benar, tidak ada yang dibaca atau ditulis. Lalu sheet dibuka dengan hak akses akun robot.

c. Membaca

if (req.op === 'read') {
  return out_({ values: (req.ranges || []).map(function (r) {
    const range = range_(ss, r, false);
    return range ? trim_(range.getDisplayValues()) : [];
  }) });
}

Untuk setiap range, misalnya 'INSPECTION TRACK OPEN 2026'!B5:Q3000, robot mengambil teks persis seperti yang terlihat di sheet (getDisplayValues). Tanggal tetap terbaca 04/11/2026, HM tetap 10615,0. Baris kosong di ujung dibuang (trim_) supaya kiriman kecil.

d. Menulis, dengan kunci dan penjaga

if (req.op === 'write') {
  const lock = LockService.getScriptLock();
  lock.waitLock(20000);
  try {
    const taken = (req.guard || []).some(function (r) { ... ada isinya? ... });
    if (taken) return out_({ error: 'taken', message: 'Baris sudah terisi.' });
    (req.data || []).forEach(function (d) {
      range_(ss, d.range, true).setValues(d.values);
    });
    SpreadsheetApp.flush();
  } finally {
    lock.releaseLock();
  }
  return out_({ ok: true });
}
  • LockService: kalau dua HP menyimpan bersamaan, yang kedua menunggu sampai yang pertama selesai (maksimal 20 detik). Jadi dua tulisan tidak saling timpa.
  • guard: daftar sel yang harus masih kosong, yaitu kolom CODE UNIT dan PROBLEM di baris tujuan. Kalau sudah terisi (keburu dipakai HP lain), robot menolak dengan taken dan server mencari baris kosong berikutnya.
  • setValues mengisi sel seperti orang mengetik: teks =IF(...) menjadi rumus, 14/11/2026 dibaca sebagai tanggal seperti biasa. Teks dari mekanik yang diawali =, +, - atau @ diberi tanda ' oleh server, supaya tidak berubah jadi rumus.

e. Pembantu

function range_(ss, a1, grow)  // "'TAB'!B5:Q3000" -> range di tab itu
function trim_(rows)           // buang baris kosong di ujung
function out_(o)               // kirim balik sebagai JSON
function doGet()               // tes dari browser: {"ok":true,"sheet":"..."}

range_ mencari tab dari namanya. Saat membaca, baris yang melewati ujung tab dipotong. Saat menulis, tab ditambah barisnya kalau perlu. Tab yang namanya tidak ada dibalas error: "range", dan server mengubahnya menjadi pesan "Nama tab di sheet berubah".

6. Cara memasang (sekali saja, tanpa kartu kredit)

  1. Buat Gmail robot. Misalnya mymanual.robot@gmail.com. Isi nomor HP dan email pemulihan milik perusahaan, lalu simpan password-nya di tempat yang bisa dibuka minimal dua admin.
  2. Jadikan robot Editor sheet. Pemilik sheet: Share, masukkan email robot, pilih Editor.
  3. Buat kode rahasia. Teks acak panjang, misalnya 32 huruf dan angka campur. Jangan dikirim di grup WA.
  4. Buat proyek skrip. Masuk sebagai akun robot, buka script.google.com, pilih New project. Hapus isinya, tempel seluruh isi tools/daily-inspection.gs, ganti GANTI_DENGAN_KODE_RAHASIA dengan kode dari langkah 3, lalu Save. Beri nama proyek, misalnya "MyManual Daily Inspection".
  5. Deploy sebagai Web App. Deploy > New deployment > jenis Web app. Execute as: Me (akun robot). Who has access: Anyone. Klik Deploy, lalu Authorize access dan pilih akun robot. Kalau muncul "Google hasn't verified this app", pilih Advanced > Go to … (unsafe). Ini wajar karena skrip buatan sendiri.
  6. Salin link Web app (berakhiran /exec). Tes dengan membukanya di browser. Hasilnya harus seperti {"ok":true,"sheet":"MASTER DATA MONITORING DAILY INSPECTION"}.
  7. Simpan dua GitHub secret di repo (Settings > Secrets and variables > Actions): SHEET_SCRIPT_URL berisi link dari langkah 6, dan SHEET_SCRIPT_KEY berisi kode dari langkah 3.
  8. Merge PR atau jalankan ulang workflow "Deploy AI server". Workflow mengunggah kedua secret ke server. Setelah itu tile Daily Inspection di app langsung bisa dipakai.
Kenapa "Anyone" aman? "Anyone" artinya link boleh dipanggil tanpa login Google. Tapi tanpa kode rahasia robot menolak semuanya. Link dan kode hanya ada di GitHub secret dan di server.

7. Perawatan

KejadianYang dilakukan
Ganti tahun (tab baru "… OPEN 2027")Ubah INSPECTION_TAB di ai-worker/wrangler.toml, lalu merge. Skrip robot tidak perlu diubah.
Kode rahasia bocorBuat kode baru. Ganti KEY di skrip lalu Deploy > Manage deployments > edit (pensil) > Version: New version > Deploy (link tetap sama). Ganti GitHub secret SHEET_SCRIPT_KEY, lalu jalankan ulang "Deploy AI server".
Kode skrip diubahSetelah Save, wajib Manage deployments > edit > New version. Tanpa langkah ini, Web App tetap memakai versi lama. Jangan pilih "New deployment", karena itu membuat link baru.
Pemilik sheet pindah ke file baruGanti SHEET_ID di skrip (lalu New version) dan INSPECTION_SHEET_ID di wrangler.toml. Jadikan robot Editor di file baru.
Admin yang pegang akun robot keluarGanti password akun robot dan serahkan ke admin berikutnya. Skrip, link dan kode tetap jalan.

Setiap malam pukul 04.00 WIB server mencoba membaca sheet lewat robot. Kalau gagal, admin melihat bar merah di layar Daily Inspection berisi penyebabnya.

Batas Google untuk akun Gmail gratis jauh di atas pemakaian 50 mekanik. Setiap simpan berjalan beberapa detik, dan satu panggilan Web App boleh berjalan sampai 6 menit.
